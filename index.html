Vendor Performance Analytics

Validated data mart → KPI engine → statistical inference → executive deliverables

View repo →

An end-to-end commercial analytics build over a wine & spirits distribution dataset. Raw operational CSVs are validated into a canonical vendor–brand data mart, fed through a reusable KPI engine, then put through concentration, profitability and inventory-risk analysis. The output is a Streamlit app, a Power BI dashboard and an auto-generated executive PDF.

Business question: where is procurement over-concentrated, which capital is trapped in slow-moving stock, and which vendor–brand combinations actually destroy margin?

  • Quality gate — schema validation, numeric coercion, missing/duplicate checks, zero/negative/infinite profiling and IQR outlier reporting. Outliers are flagged, never silently dropped.
  • Concentration — Pareto, ABC segmentation and Herfindahl–Hirschman Index over purchase spend.
  • Inference — Pearson/Spearman correlation, Welch's t-test, Mann–Whitney U, Cohen's d and bootstrap confidence intervals.
  • Decision layer — vendor/brand quadrants, inventory risk scoring and working-capital scenarios.

Opti-Workbench — CVaR Portfolio Optimisation Benchmark

Exact MILP vs. metaheuristics under matched budgets · blind-review research manuscript

View repo →

Use case. Allocate capital across 100 U.S. metropolitan housing markets under a tail-risk objective. The data are FHFA purchase-only house-price indexes — 139 quarterly returns spanning 1991Q2–2025Q4 — evaluated over 24 rolling origins with a 40-quarter training window, 4-quarter holdout and 4-quarter step. A four-index listed-REIT panel is retained as a tradable robustness domain.

The research question. Portfolio papers routinely compare algorithms before establishing whether the underlying program is convex or mixed-integer. This project reverses that: it first fixes the formulation, solves it exactly, and only then asks when stochastic search is worth reaching for.

Why it matters. The metropolitan indexes are proxies, not directly investable assets, so the study is framed as a computational benchmark rather than an investment claim — a distinction the manuscript enforces throughout.

Optimisation models

P3 — continuous allocation Linear program

maxw   A·r̄Tw − λ·CVaRα(w) − c·τ(w, w0)

Annualised mean return, penalised by empirical Conditional Value-at-Risk and by proportional turnover against an equal-weight reference. Rockafellar–Uryasev's auxiliary-threshold representation makes the tail term linear, so the whole problem is an LP with a certifiable global optimum.

  • Σwi = 1, long-only, 0 ≤ wi ≤ 15%
  • α = 0.90 · λ = 1 · c = 25 bp per unit turnover

P4 — cardinality-constrained Mixed-integer LP

same objective, plus binary selectors zi ∈ {0,1}

Adds a genuine combinatorial structure: a position is either off, or on with a real minimum size. This is what turns the crossover question from rhetorical into substantive — and what the exact comparator is there to anchor.

  • ℓizi ≤ wi ≤ uizi — 2% buy-in floor, 15% cap
  • Σzi ≤ K = 10 active positions

Smart RC Car — Multiple Autonomous Modes

ESP32 embedded robotics · 4-person team, VIT Vellore · working hardware

Hardware demo below

A mecanum-wheeled autonomous ground robot built around an ESP32 microcontroller and programmed in MicroPython. The vehicle switches at runtime between four operating modes, fusing a three-channel IR array and a servo-mounted ultrasonic rangefinder to close the loop between sensing and motion.

  • Line tracking — the IR array reads black/white contrast across three ADC channels and biases left/right motor speed to hold the path
  • Obstacle avoidance — HC-SR04 range readings trigger a stop or reroute once an obstacle crosses the distance threshold
  • Object following — the servo pans the ultrasonic sensor to track a target and modulates motor speed to hold a set standoff distance
  • Standby — motors idle and sensors stay live while the controller waits for a mode command over Wi-Fi

Mode selection runs over a non-blocking TCP socket, so the robot can be re-tasked live without reflashing — the same base platform then extends to IoT and remote-operation use cases.

House Price Prediction

Supervised regression pipeline with cross-validated evaluation

View repo →

A tabular regression problem where most of the work sits upstream of the model. Raw property records carry mixed types, missing fields and skewed target values, so the pipeline is built so that every transformation is fitted inside the cross-validation loop rather than on the full dataset — the difference between an honest error estimate and a leaked one.

  • Feature engineering — derived size, age and ratio features from the raw property attributes
  • Categorical encoding — nominal fields encoded for the estimator without inventing ordinal structure
  • Missing values — imputed inside the fold, so no test-fold information leaks into the imputer
  • Evaluation — k-fold cross-validated RMSE for error in target units, R² for explained variance

Titanic Survival Prediction

Binary classification with error analysis on a 179-passenger hold-out

View repo →

A logistic regression classifier trained on passenger class, sex, age and fare. The interesting part is not the headline accuracy but what the confusion matrix exposes: the model is noticeably better at predicting who died than who survived.

  • Preprocessing — missing ages filled by mean imputation; categorical variables encoded
  • Model — logistic regression on class, sex, age and fare
  • Error analysis — a confusion-matrix heatmap surfaced a false-negative skew on survivors, with recall (0.73) trailing precision (0.77)
  • Reading it — the model under-predicts survival, so it misses real survivors more often than it raises false alarms; on an imbalanced target, accuracy alone would have hidden this
