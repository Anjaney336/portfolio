Quant engineering / execution research

Quant Execution Lab

Deterministic matching and auditable execution experiments.

Scope: Python, one instrument, one writer, synthetic data. This project demonstrates algorithms, recovery logic and research controls; it is not production trading infrastructure.

Architecture

Validated order → price heap + FIFO queue → partial fills → result ledger. For persisted operation: apply to a candidate state → SQLite transaction → replace live state. Restart replays the event chain and verifies results.

Engineering choiceReason
Integer ticks and quantitiesAvoid ambiguous floating-point price comparisons.
Independent sorted-list oracleCompare matching against a different algorithm across 5,000 events.
Event IDs and stored responsesIdentical retries are idempotent; conflicts fail.
Transaction before state replacementRejected writes do not become accepted in-memory events.
Replay/hash checksDetect accidental event/result corruption; not authenticated security.

Paired execution experiment

Buy 100 units over 20 steps, using a fixed limit 10 ticks above arrival mid and assumed 1 bp fees. Immediate scheduling attempts all remaining units at each step. TWAP targets elapsed-time proportional quantity and catches up after missed fills.

Both policies see the same path for each of 100 seeds. The three ask levels replenish independently at every step. No persistent impact or adverse-selection model is fitted.

Shortfall: executed price cost + fees + unfilled quantity × terminal price change, divided by parent arrival notional. Missed fills are not ignored or forced through at an invented price.

Conditional resultValue
Paired TWAP minus immediate shortfall−1.286 bp
95% paired bootstrap interval (2,000 resamples)−2.050 to −0.521 bp
Published observations100 paired paths / 200 executions

The comparison is specific to the assumed generator. Independent replenishment favours scheduling across time; these figures do not establish real-market execution savings.
